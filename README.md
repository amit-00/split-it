# Split It

Fresh TypeScript Cloudflare Workers scaffold for sharing expenses with friends. The previous Django app was removed in commit `6742d99`, preserving Git history.

## Included

- A small same-origin web interface with Google sign-in and sign-out.
- Better Auth with the Drizzle SQLite adapter and Cloudflare D1.
- Database-backed sessions and a protected `GET /api/me` endpoint.
- Auth tables (`user`, `account`, `session`, `verification`) and a versioned SQL migration.
- `GET /api/health` verifies the migrated database and reports whether auth is configured.
- Workers runtime integration tests. Expense/group/balance features are not implemented yet.

Google is the sole sign-in provider. Email/password sign-up and sign-in are disabled. First Google sign-in creates an account. Only OpenID, email and profile scopes are requested; there is no Gmail inbox access or gmail.com domain restriction. The standard auth schema includes a nullable password field for adapter compatibility; password authentication remains disabled.

## Run locally

Use Node.js 22 or newer and npm. From this repository directory:

```sh
npm ci
cp .dev.vars.example .dev.vars
npm run db:migrate
npm run dev
```

Open http://localhost:8787. Local D1 works with the checked-in placeholder database ID, without creating a Cloudflare database. The landing page and health endpoint work before credentials are configured; auth endpoints return a setup error until configuration is complete.

Set these values in the ignored `.dev.vars` file:

- `BETTER_AUTH_URL=http://localhost:8787`
- `BETTER_AUTH_SECRET`: generate a random value with `openssl rand -base64 32`.
- `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET`: use your own Google OAuth web application credentials.

In Google Cloud Console, configure the OAuth consent screen and create a **Web application** OAuth client. Register `http://localhost:8787` as the JavaScript origin and `http://localhost:8787/api/auth/callback/google` as the authorized redirect URI. Add yourself and friends as test users while the consent screen is in testing. Restart the dev server after changing `.dev.vars`. Never commit credentials.

## Verify and develop

```sh
npm run check       # Generate runtime types and typecheck
npm test            # Dry-run build, then isolated Workers/D1 auth integration tests
npm run db:generate # Generate migration after editing src/db/schema.ts
npm run db:migrate  # Apply pending migrations to local D1
```

Tests use synthetic OAuth credentials and do not contact Google. They verify scopes/callback/state, disabled email authentication, unknown providers, origin checks, and real D1 session lookup, expiry, tampering and revocation. Real Google callback/token exchange requires your credentials and a browser sign-in.

Source: `src/index.ts` routes requests; `src/auth.ts` configures auth per request; `src/db/schema.ts` owns database schema; `public/` contains the frontend. `worker-configuration.d.ts` is generated by Wrangler. D1 does not support Drizzle interactive transactions, so the auth adapter explicitly disables them.

Dependency audit at setup: four moderate development-only findings originate from Drizzle Kit's transitive legacy esbuild tooling. Production dependencies have no reported findings. The affected esbuild development server is not used by this scaffold; Wrangler serves local development. Revisit when Drizzle Kit releases an updated stable dependency tree.

## Cloudflare configuration for a later deployment

No cloud resources have been created and nothing has been deployed. When ready, create a D1 database with `npx wrangler d1 create split-it` and replace `database_id` in `wrangler.jsonc` with its returned ID. Configure `BETTER_AUTH_URL` for your HTTPS origin and store `BETTER_AUTH_SECRET`, `GOOGLE_CLIENT_ID`, and `GOOGLE_CLIENT_SECRET` with `wrangler secret put`. Register the matching production Google callback URI. Apply migrations remotely before deploying. The `build` script is dry-run only.
