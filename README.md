# Split It

TypeScript/Hono Cloudflare Workers API for sharing expenses with friends. The previous Django app was removed in commit `6742d99`, preserving Git history.

## Included

- A small same-origin web interface with Google sign-in and sign-out.
- Better Auth in stateless mode: encrypted, signed cookies hold session and OAuth state data. No database is required for authentication or session checks.
- A protected `GET /api/me` endpoint and a `GET /api/health` endpoint that reports whether auth credentials are configured.
- A D1-backed API for standalone expenses, optional groups, settlements, currency-separated balances, and retained audit history. Financial writes use retry keys and optimistic versions.
- Workers/D1 integration tests, deterministic splitting checks, and real Better Auth verification using synthetic signed Google tokens.

Google is the sole sign-in provider. Email/password sign-up and sign-in are disabled. Only OpenID, email, and profile scopes are requested; there is no Gmail inbox access or gmail.com domain restriction.

## Run locally

Use Node.js 22.18 or newer and npm. From this repository directory:

```sh
npm ci
cp .dev.vars.example .dev.vars
npm run db:migrate
npm run dev
```

Open http://localhost:8787. The landing page and health endpoint work before credentials are configured; auth endpoints return a setup error until configuration is complete.

Set these values in the ignored `.dev.vars` file:

- `BETTER_AUTH_URL=http://localhost:8787`
- `BETTER_AUTH_SECRET`: generate a random value with `openssl rand -base64 32`.
- `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET`: use your own Google OAuth web application credentials.

In Google Cloud Console, configure the OAuth consent screen and create a **Web application** OAuth client. Register `http://localhost:8787` as the JavaScript origin and `http://localhost:8787/api/auth/callback/google` as the authorized redirect URI. Add yourself and friends as test users while the consent screen is in testing. Restart the dev server after changing `.dev.vars`. Never commit credentials.

## Session behavior

Better Auth uses a signed session token cookie and an encrypted session data cookie. Sessions expire after seven days. Sign-out clears the browser's session cookies. Because there is no server-side session record, a copied cookie remains valid until it expires; rotating `BETTER_AUTH_SECRET` invalidates all sessions. Verified Google subjects resolve atomically to durable D1 app users. `/api/me` returns this stable ID; legacy sessions without the protected app identity must sign in again. Email changes refresh profile data without changing financial ownership. The auth factory remains request-local to prevent concurrent sign-ins from sharing identity state. See [the data model](docs/data-model.md).

## Verify and develop

```sh
npm run check  # Generate runtime types and typecheck
npm test       # Dry-run build, then money/auth/Workers/D1 tests
```

Tests use synthetic OAuth credentials and signed tokens; Google certificate fetching is mocked, so tests do not contact Google. They verify the requested scopes, callback and state, disabled email authentication, origin checks, encrypted cookie authentication, tampering, expiry, and sign-out. The D1 test verifies standalone settlements, optional expense groups, and currency-separated balances. A live browser OAuth callback still requires your own Google credentials. No lint tool is configured; verification uses TypeScript diagnostics, tests, and `git diff --check`.

Data model: `migrations/0000_expense_model.sql` defines the D1 tables and indexes; [docs/data-model.md](docs/data-model.md) explains standalone records, optional groups, and query paths. The initial migration was rewritten while there was no live data; discard any local D1 state that applied its earlier grouped-only draft before running `npm run db:migrate`. Apply both checked-in migrations with `npm run db:migrate`. `0001_core_api.sql` adds versions, audit/retry receipts, lookup limits and final-balance assertion constraints without rewriting the baseline. Source: `src/index.ts` registers Hono routes; `src/auth.ts` configures auth per request; `public/` contains the frontend. `worker-configuration.d.ts` is generated by Wrangler.

## API usage

See [API contracts and examples](docs/api.md) and the [approved design](docs/superpowers/specs/2026-09-21-expense-core-design.md). Registered users can find each other by exact email, create CAD/USD expenses with equal or exact splits, and record external settlements. Only expense creators, settlement recorders, and group owners control their respective records.

## Cloudflare configuration for a later deployment

No cloud resources have been created and nothing has been deployed. Before using financial data in production, create a D1 database, replace the placeholder database ID in `wrangler.jsonc`, and apply the migration remotely. When ready, configure `BETTER_AUTH_URL` for your HTTPS origin and store `BETTER_AUTH_SECRET`, `GOOGLE_CLIENT_ID`, and `GOOGLE_CLIENT_SECRET` with `wrangler secret put`. Register the matching production Google callback URI. The `build` script is dry-run only.
